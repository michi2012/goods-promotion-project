# 포트폴리오 기록

면접·포트폴리오에서 설명할 만한 일을 이야기 형태로 남긴다. 세부는 원본 문서로 링크하고 여기에 복제하지 않는다.

| 문서 | 쓰는 내용 |
|------|------|
| `docs/design-notes.md` | 개발자용 — 왜 이렇게 했는지, 지켜야 할 불변식 |
| `docs/incidents/` | 장애 원인 분석(RCA) |
| `docs/specs/` | 기능의 요구사항·설계 결정 |
| **이 문서** | 문제 → 검토한 대안 → 결정 → 결과(수치·증거) 요약 + 원본 링크 |

## 문제 해결·설계 결정

기능·작업이 끝났을 때(PR 머지 후) 기록 가치가 있으면 추가한다. 기준: 트레이드오프가 있었고, 결과를 수치·테스트·E2E로 보여줄 수 있는 것.
- **기능 단위로 묶어 한 줄**로 적는다 (면접에서 몇 분 설명할 만한 크기). 여러 PR로 나눈 기능은 마지막 PR 머지 후 한 번에 적는다.
- 리뷰 지적 반영·알람 조정 같은 개별 수정은 따로 적지 않는다. 필요하면 그 기능 이야기를 풀 때 세부로 꺼낸다.

| 날짜 | 주제 | 문제 | 검토한 대안 → 결정 | 결과·증거 | 원본 |
|------|------|------|------|------|------|

## 성능 개선

perf-compare로 측정한 개선을 한 줄씩 요약한다. 측정 원본(조건·반복 수치·보조 지표)은 `docs/perf/`에 있다.
- 개선 하나 = 한 줄. 나빠졌거나 차이가 없던 시도도 적는다.
- 수치는 반복 측정의 중앙값, 환경(로컬/클라우드)을 함께 적는다.
